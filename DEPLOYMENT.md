# Публикация Creeps

Репозиторий: https://github.com/avvolkova13/creeps . Версия для показа: https://avvolkova13.github.io/creeps/ . Пользователь выбрал публикацию актуального интерфейса на GitHub Pages без подключения серверного хостинга.

## Версия для показа на GitHub Pages

Обновление кабинета 2026-09-14: заполненный пример кабинета открывается из шапки, показывает все пункты ТЗ и встроенную корзину. Условный профиль не является авторизацией Steam; локальное сохранение ссылки не подтверждает её владельца. Состояния операций и заказов обозначены как примеры. Подробности — `docs/account-presentation-plan.md`; статус публикации — `TASK.md`.

Без `CREEPS_APP_URL` workflow публикует 73 маршрута: главную, каталог, 68 страниц товаров, кабинет, отдельную корзину `/cart` и вход `/login`. Работают навигация, фильтры, сортировка, калькулятор, расчёт комиссии 5% и демонстрационная корзина. Выбор товаров сохраняется в sessionStorage вкладки; это не заказ, резерв или подтверждение наличия.

«Оформить заказ» у гостя открывает страницу входа с возможностью вернуться в корзину без потери выбора. Настоящая авторизация, проверка профиля и оплата в Pages не выполняются; при попытке операции интерфейс сообщает о неудаче. По запросу пользователя служебные подписи о демо и показе удалены. Баланс не зачисляется, покупки не создаются. Обычная серверная сборка сохраняет настоящий Steam-вход и возвращает после него в корзину.

```sh
npm run build:pages
npm run check:pages
```

Скрипт выставляет `STATIC_EXPORT=1`, `NEXT_PUBLIC_SHOWCASE_PREVIEW=1` и basePath репозитория только на время сборки. Результат находится в `out/`; `pages-build.json` содержит режим, revision и 71 маршрут. Не задавать preview-флаг для рабочего сервера.

## GitHub Actions

Каждый запуск проверяет lint, тесты, TypeScript, обычную сборку, сборку Pages и её маршруты/ресурсы. Push в main публикует артефакт через deploy-pages; pull request только проверяется. После публикации сверить revision в pages-build.json с коммитом и проверить внешний сайт в браузере.

Если разработчик позднее задаст repository Variable `CREEPS_APP_URL` с HTTPS-origin работающего Node-приложения, Pages станет набором перенаправлений на него. Сейчас для показа эта переменная не нужна.

## Серверная версия

Вход Steam, кабинет и корзина требуют Node.js 24. GitHub Pages не запускает серверные процессы. `npm start` теперь поднимает Next и API на одном порту; прямой `next start` поднимет только интерфейс.

Локально:

```sh
npm ci
npm run lint
npm test
npm run typecheck
npm run build
npm start -- --port 3100
```

Настройки `.env.example`:

- `APP_ORIGIN`: точный публичный HTTPS-origin без завершающего слеша. Используется для callback Steam и проверки Origin. Нельзя определять его по непроверенному Host или X-Forwarded-Host.
- `HOST`: 127.0.0.1 локально; 0.0.0.0 за настроенным HTTPS-прокси. Для публичного listener APP_ORIGIN обязателен.
- `PORT`: 3100 по умолчанию.
- `DATABASE_PATH`: файл SQLite на постоянном диске. `.data/` и `*.sqlite*` исключены из Git. База содержит закрытые профили, сессии и trade-URL.

Запускать один экземпляр приложения. Для горизонтального масштабирования потребуется общий store и ограничитель запросов. HTTPS-прокси должен обслуживать весь origin, включая `/api/`; кэширование API запрещено. Секреты не передавать в NEXT_PUBLIC_*.

Подготовлен Dockerfile с непривилегированным пользователем и `/data` для постоянного тома. Образ в этой среде не собирался: Docker отсутствует. Обязательная проверка после развёртывания — `/api/health`, вход/отмена/выход Steam, сохранение trade-URL и корзины после перезапуска контейнера. SQLite резервировать штатным online backup или при остановленном приложении, не копировать один основной файл во время WAL-записи.

## Незавершённые интеграции

Провайдер оплаты, поставщик Steam-пополнения и коммерческий API скинов неизвестны. Пока сервер не создаёт платёж, денежное зачисление или заказ. Контракты должны определить актуальную цену/резервирование, способы оплаты, точность сумм и комиссию, создание checkout, доверенную проверку результата, идемпотентные webhook и выдачу. Возврат пользователя с платёжной страницы не является подтверждением оплаты.

Ключи только в окружении сервера. Steam OpenID ключа не требует. Существование публичного профиля проверяется на Steam Community; это не подтверждает его пригодность для пополнения у конкретного провайдера.
