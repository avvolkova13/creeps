## Запуск и проверки

Node.js 24 LTS; рабочее окружение этапа — 24.15.0, npm 11.12.1. Версии зависимостей фиксируются в package.json и package-lock.json.

```sh
npm ci
npm run dev
```

По умолчанию сервер доступен на http://127.0.0.1:3000. Для другого порта: `npm run dev -- --port 3100`.

```sh
npm run lint
npm run typecheck
npm test
npm run build
npm start
```

`pretypecheck` генерирует типы маршрутов перед `tsc`. Тесты валюты, ввода и фильтрации используют встроенный Node test runner и поддержку TypeScript в Node 24; отдельный тестовый фреймворк не установлен. Сайт закрыт от индексации до готовности продукта; перед запуском магазина пересмотреть metadata robots.

Ограничение инструментов: ESLint закреплён на 9.39.5, который npm помечает как устаревший. Текущий eslint-config-next 16.3.4 использует eslint-plugin-react 7.37.5 с поддержкой ESLint до 9; на ESLint 10 правило react/display-name падает. Не форсировать несовместимые peer dependencies. Обновить линтер вместе с совместимыми плагинами, когда такой набор будет доступен.

## Что создано

- `src/app/` — общая оболочка, главная `/`, каталог `/catalog`, товар `/catalog/[id]`, загрузка каталога и 404. Палитра исправлена по тёмным вступительным экранам TEN и скриншотам пользователя: сине-серый фактурный фон, ледяной голубой текст, тёмные подложки 86%. Локальные Unbounded и Manrope с кириллицей подключены как похожие шрифты, лицензии OFL лежат в public/fonts/.
- `src/components/` — навигация, конвертер, две отдельные формы, фильтры, список и полная карточка/диалог товара, состояния данных. FAQ содержит четыре согласованные темы.
- `src/config/project.ts` — только подтверждённые публичные данные: валюта, курс, почта, карта и СБП. Наличие способа оплаты в конфигурации не означает подключение провайдера.
- `src/lib/currency.ts` — справочные конвертация и форматирование, без комиссий и правил списания.
- `src/lib/catalog.ts` — внутренняя модель отображения и фильтрация. `catalog-source.ts` отдаёт утверждённый снимок SkinSwap/SkinBaron. Это не коммерческий API вендора и не подтверждение наличия в Creeps.
- `src/lib/amount-input.ts` — строгий разбор десятичного ввода с точкой/запятой, без знаков и экспоненты.
- `tests/` — 19 проверок курса, ввода, фильтров, целостности снимка и пересчёта исходных цен. Синтетические записи в тесте алгоритма не импортируются в приложение и не являются ассортиментом.

Кабинет, корзина, вход и платежи не подключены: навигация объясняет недоступность, отправка форм отключена. Пополнение Steam не использует Creeps или корзину; локальный ввод ID не считается подтверждением существования аккаунта. Новые зависимости не добавлялись.

Пользователь прямо выбрал SkinSwap и SkinBaron источниками временного наполнения. Загружены 68 записей CS2 и пять категорий; изображения сохранены локально. Главная показывает 12 карточек, каталог — все импортированные. Работают поиск, фильтры, быстрый просмотр и полные страницы с реальными данными. Покупка пока отключена.

Обновление: `npm run import:catalog`, затем `npm test`, `npm run build` и перезапуск production-сервера. Автоматическое расписание не настроено. Подробности источников, описаний, валютного пересчёта и ограничений: [catalog-import.md](reference-evidence/catalog-import.md). Снимок — `src/data/catalog-snapshot.json`, русские пересказы описаний — `src/data/product-descriptions.json`.

## Херо и визуальные источники

`src/components/skin-hero.tsx` и CSS Module адаптируют [Magic UI Marquee / Marquee 3D](https://magicui.design/docs/components/marquee), полученный через установленный MCP-плагин. Встречные ленты используют CSS transforms; пауза доступна кнопкой и наведением, движение останавливается вне экрана и в скрытой вкладке. При reduced motion показаны статичные карточки. Пакет анимаций не установлен.

Неоновый лаймовый `#B2FF59` выбран по последнему скриншоту Wembi; основная палитра остаётся синей по TEN. Четыре реальные иллюстрации из страницы SkinSwap хранятся в `public/hero-skins/`; происхождение — в `sources.json`. Они явно подписаны как примеры, не связаны с каталогом и не подтверждают наличие. Конвертер расположен сразу под херо, затем следуют категории, витрина, отдельные пополнения и FAQ из ТЗ.

## Валютные расчёты

Курс берётся из единого публичного конфига. `estimateRublesFromCreeps` и `estimateCreepsFromRubles` возвращают числа только для справочного отображения. Десятичная арифметика JavaScript не является платёжным расчётом.

`formatEstimatedAmount` требует явно указать число знаков для отображения; общего правила округления по умолчанию нет. Допустимый диапазон 0–100 относится к формату Intl, не к точности Creeps. Функции не применяются к серверным балансам, списаниям или запросам провайдера. Q7 остаётся открытым; расчёт платежей требует согласованной денежной точности и контракта провайдера.

## Границы будущих интеграций

Страницы и layout остаются серверными компонентами. Клиентские компоненты обслуживают интерактивные поля и состояния. [Основание: документация Next.js](https://nextjs.org/docs/app/getting-started/server-and-client-components).

| Область | Доверенная серверная ответственность | Что можно передать браузеру | Недостающие данные |
| --- | --- | --- | --- |
| Каталог вендора | Запрос и проверка фактического ассортимента, цены и доступности | Данные для карточек/фильтров | Q4: контракт API и доступы |
| Steam-вход | Проверка авторизации, серверная сессия и выход | Безопасные данные текущего пользователя | Документация авторизации и конфигурация приложения |
| Creeps и операции | Баланс, история, подтверждённое зачисление | Баланс/история для отображения | Q6/Q7, хранилище и контракт |
| Корзина и заказы | Проверка состава, актуальной цены, владельца и согласованного способа покупки | Состав и статусы | Q1/Q4/Q6 |
| Прямое пополнение Steam | Проверка Steam ID, создание отдельной операции и её оплаты | Результат проверки, платёжный переход | Q5/Q6/Q7 |
| Оплата и выдача | Проверка результата провайдера, защита от повторного зачисления/выдачи, связь платежа с заказом | Подтверждённый статус и понятная ошибка | Контракты платежей, webhook/проверки статуса и выдачи |

Эта таблица фиксирует границы ответственности, а не выдуманные интерфейсы API. Конкретные типы ответов, endpoints и адаптеры будут созданы после получения документации. Тогда серверные модули следует изолировать от client imports; секреты хранятся в серверном окружении и никогда не в `NEXT_PUBLIC_*` или публичном конфиге.

Ввод Steam ID в форме пополнения не авторизует пользователя. Прямое пополнение Steam не использует корзину и баланс Creeps. Возврат с платёжного сайта сам по себе не подтверждает успех. Неизвестный баланс нельзя подменять нулём, а недоступный API — успешным пустым ответом.

Будущие состояния: загрузка, данные, пустой результат, ошибка, недоступная интеграция. Для проверки Steam ID различать «пользователь не найден» и сбой сервиса. До реальных контрактов эти состояния не имитируют работающие операции.

## Перед следующими этапами

Открытые бизнес-вопросы хранятся в PROJECT.md. До реализации покупки нужен Q1, до интеграций — документация и доступы, до платёжных расчётов — Q7. Точность до двух знаков в текущем интерфейсе используется для справочного представления; перед показом реальных цен сверить их единицы и точность с поставщиком. Не использовать округлённые UI-значения как сумму заказа. Следующий этап — кабинет, корзина и баланс после разрешения пользователя; незавершённая приёмка реального ассортимента остаётся отдельной зависимостью.
